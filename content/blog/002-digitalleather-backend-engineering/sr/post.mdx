Moj rad u DigitalLeather-u prerastao je u DevOps ulogu u kojoj sam bio odgovoran za infrastrukturu, automatizaciju deployment-a i pouzdanost produkcije kroz VPS i on-premises okruženja.

Ovaj posao se prirodno nadovezao na moje prethodno iskustvo jer spaja praktičan IT rad sa softverskim inženjeringom: Linux servere, mreže, deployment aplikacija, kontejnerizovane servise, bezbednosnu konfiguraciju i svakodnevnu disciplinu održavanja sistema koji su razumljivi i ponovljivi.

<ContentBlock title="Infrastruktura od nule">
  Dizajnirao sam i postavio kompletnu infrastrukturu za VPS i on-premises deployment okruženja.

Rad je počeo pripremom Linux servera, a zatim prerastao u kompletnu osnovu za deployment aplikacije: domene, subdomene, firewall pravila, Nginx konfiguraciju, SSL/TLS, runtime konfiguraciju aplikacije i deployment tokove za više okruženja.

  <Section title="Glavne odgovornosti">
    - Postavljanje VPS i on-premises okruženja od nule.
    - Priprema Linux servera za deployment aplikacije.
    - Konfiguracija Nginx-a, SSL/TLS-a, DNS-a, subdomena i firewall pravila.
    - Security hardening kroz deployment stack.
  </Section>
</ContentBlock>

<ContentBlock title="Docker okruženja">
  Veliki deo uloge bio je da aplikacija može konzistentno da se pokreće i deploy-uje.

Kontejnerizovao sam servise koristeći Docker i Docker Compose kroz razvojno, demo i produkciono okruženje. To je deployment učinilo predvidljivijim i pomoglo da se smanje razlike između lokalnog razvoja, testiranja, demo okruženja i produkcije.

  <Callout type="info" title="Zašto je ovo važno">
    Cilj je bila ponovljivost. Kada su servisi upakovani i konfigurisani konzistentno, tim troši manje vremena na razlike između okruženja, a više vremena na unapređenje proizvoda.
  </Callout>
</ContentBlock>

<ContentBlock title="CI/CD kroz GitHub Actions">
  Izgradio sam i održavao CI/CD pipeline-ove koristeći GitHub Actions, automatizujući build i deployment životni ciklus.

Pipeline-ovi su pokrivali praktičan rad koji je potreban svakom produkcionom sistemu: build servisa, pripremu Docker image-a, prolazak promena kroz deployment tok i smanjenje zavisnosti release procesa od ručnog rada na serverima.

  <Section title="Šta su pipeline-ovi podržavali">
    - Automatizovan build aplikacionih servisa.
    - Docker-based deployment workflow-e.
    - Ponovljive deployment korake za demo i produkciono okruženje.
    - Brže i sigurnije release-ove kroz GitHub Actions.
  </Section>
</ContentBlock>

<ContentBlock title="Pouzdanost produkcije">
  DevOps nije samo deployment koda. Važno je razumeti i šta se dešava nakon deployment-a.

Postavio sam monitoring i logging kako bi tim imao bolju vidljivost stanja sistema i mogao brže da reaguje kada nešto zahteva pažnju. Radio sam i na operativnim detaljima oko pristupa serverima, konfiguracije, mrežnih pravila, sertifikata i ponašanja servisa kroz različita okruženja.

Ovaj deo posla zahteva pažljivo razmišljanje jer male infrastrukturne odluke mogu kasnije napraviti velike troškove održavanja. Trudio sam se da setup bude praktičan, bezbedan i dovoljno jasan da tim može da ga koristi i održava.

</ContentBlock>
