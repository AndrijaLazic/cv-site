My DigitalLeather work grew into a DevOps-focused role where I was responsible for infrastructure, deployment automation, and production reliability across VPS and on-premises environments.

That work fit naturally with my background because it connected practical IT experience with software engineering: Linux servers, networking, application deployment, containerized services, security configuration, and the day-to-day discipline of keeping systems understandable and repeatable.

<ContentBlock title="Infrastructure from scratch">
  I designed and set up the full infrastructure for both VPS and on-premises deployment environments.

The work started with preparing Linux servers and grew into the full deployment foundation around the application: domains, subdomains, firewall rules, Nginx configuration, SSL/TLS, application runtime configuration, and deployment paths for multiple environments.

  <Section title="Core responsibilities">
    - Set up VPS and on-premises environments from the ground up.
    - Prepared Linux servers for application deployments.
    - Configured Nginx, SSL/TLS, DNS, subdomains, and firewall rules.
    - Applied security hardening across the deployment stack.
  </Section>
</ContentBlock>

<ContentBlock title="Dockerized environments">
  A major part of the role was making the application easier to run consistently.

I containerized services with Docker and Docker Compose across development, demo, and production environments. This made deployments more predictable and helped reduce differences between local development, testing, demos, and production usage.

  <Callout type="info" title="Why this mattered">
    The goal was repeatability. When services are packaged and configured consistently, the team spends less time debugging environment differences and more time improving the product.
  </Callout>
</ContentBlock>

<ContentBlock title="CI/CD with GitHub Actions">
  I built and maintained CI/CD pipelines with GitHub Actions, automating the build and deployment lifecycle.

The pipelines handled the practical work that every production system needs: building services, preparing Docker images, pushing changes through the deployment flow, and making releases less dependent on manual server work.

  <Section title="What the pipelines supported">
    - Automated builds for application services.
    - Docker-based deployment workflows.
    - Repeatable deployment steps for demo and production environments.
    - Faster and safer releases through GitHub Actions.
  </Section>
</ContentBlock>

<ContentBlock title="Production reliability">
  DevOps work is not only about deploying code. It is also about understanding what happens after deployment.

I set up monitoring and logging so the team had better visibility into system health and could respond faster when something needed attention. I also worked on the operational details around server access, configuration, network rules, certificates, and service behavior across environments.

This part of the work required careful thinking because small infrastructure decisions can create large maintenance costs later. I tried to keep the setup practical, secure, and easy enough for the team to operate.

</ContentBlock>

<ContentBlock title="How this shaped my engineering">
  This experience made me stronger as a backend engineer because it gave me more ownership over the full lifecycle of an application.

Writing application code is one part of the job. Running it reliably is another. Working across both sides helped me think more clearly about configuration, observability, deployment risk, and the operational reality of software after it leaves a developer machine.

  <Callout type="tip" title="Main takeaway">
    My DevOps work at DigitalLeather connected backend engineering with infrastructure ownership: Docker, GitHub Actions, Nginx, Linux, VPS deployments, SSL/TLS, CI/CD, monitoring, and production reliability.
  </Callout>
</ContentBlock>
